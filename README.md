# Демо-бот записи в Telegram

Бот проводит клиента через выбор услуги, специалиста, даты и времени, затем отправляет владельцу уведомление о подтверждённой записи.

## Что нужно перед запуском

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram, выполните `/newbot` и сохраните выданный токен.
2. Создайте файл `.env` рядом с `Dockerfile` по примеру `.env.example`.
3. Вставьте токен в `TELEGRAM_BOT_TOKEN`.
4. Укажите свой числовой Telegram ID в `OWNER_CHAT_ID`. Его можно узнать через бота [@userinfobot](https://t.me/userinfobot).

Не отправляйте файл `.env` никому: в нём находится ключ управления ботом.

## Локальный запуск в Docker

В PowerShell из папки проекта выполните:

```powershell
docker build -t booking-demo-bot .
docker run --rm --env-file .env -v "${PWD}\data:/app/data" booking-demo-bot
```

После запуска откройте вашего бота в Telegram и нажмите `/start`. Для остановки нажмите `Ctrl+C` в терминале.

Папка `data` монтируется с компьютера в контейнер: в ней останется SQLite-база с записями после перезапуска контейнера.

## Проверка без Telegram

```powershell
.\.venv\Scripts\python.exe -m pytest -v
```

## Развёртывание на Koyeb

1. Создайте GitHub-репозиторий и загрузите проект, не добавляя `.env` и `data`.
2. В Koyeb выберите **Create Worker** и подключите репозиторий. Бот получает события через long polling, поэтому HTTP-порт ему не нужен.
3. Koyeb найдёт `Dockerfile`; оставьте команду запуска из образа.
4. В разделе **Environment variables** добавьте `TELEGRAM_BOT_TOKEN` и `OWNER_CHAT_ID`.
5. Выберите бесплатный инстанс, задайте ровно одну реплику и запустите деплой. Несколько процессов с одним токеном будут конкурировать за обновления Telegram.

Для демонстрации этого достаточно. На Koyeb без подключённого постоянного тома SQLite находится в файловой системе контейнера и при новом деплое может исчезнуть. Для клиентского проекта нужно заменить её на управляемую PostgreSQL-базу.
